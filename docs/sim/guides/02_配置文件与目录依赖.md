## 1．干净目录怎么装配，为什么分层

工作目录不必等于源码目录。编译产物回答“运行什么程序”，运行配置回答“程序接谁、读哪里、写哪里”。把它们从源码、旧实验生成状态中分开，可以明确一轮实验的输入与输出。

本次已用过的 C++ 目录结构可整理为：

基础 JSON 样板来自 `dist/common`；中台配置来自 `dist/QuoteFactory`；Runner 配置来自 `dist/WtRunnerCta`；Loader 配置和映射来自 `dist/LoaderRunner`。Linux 可执行文件和插件来自已有编译输出。复制后需要实际调整账户、前置、编码、UDP 端口、订阅范围、策略和执行器开关，不能直接运行上游演示账户和策略。

**三个路径概念要分开：**

1. 配置中 `../common`、`../FUT_Data` 等相对文件路径按进程工作目录解析。因此必须进入 `datahub/` 或 `run/` 后启动，或为 `docker exec` 指定正确的 `-w`。
2. Parser/Trader 插件先按工作目录的 `parsers/`、`traders/` 搜索，也会根据主模块位置回退。独立 C++ WtRunner 的执行器和策略工厂扫描工作目录的 `executer/`、`cta/`；wtpy 的 WtRtRunner 执行工厂则从 WtPorter 安装目录的 `executer/` 加载。不能把两种启动器的搜索路径混用。
3. ParserCTP / TraderCTP 再加载官方 API 时，以插件自己的模块目录为基础。当前 Linux 部署文件名是 `thostmduserapi_se.so`、`thosttraderapi_se.so`，不要把官方原生库误放到进程根目录或自行加 `lib` 前缀。

`common.seed`、SDK、适配源码与证据目录属于管理层，可不参与生产启动；`common`、行情存储和 `generated` 则有实际运行依赖。新实验不能复制旧 `generated`、CTP flow 或 `mocker_N`，否则会带入旧目标、订单标记、持仓与连接状态。

`mdparsers.yaml` 控制行情前置、账号、插件、订阅 `code` / 过滤范围以及 `active`。没有活动 parser 就没有行情源。`dtcfg.yaml.writer` 控制保存 Tick、1 分钟、5 分钟、日线与历史、CSV 开关；这不是交易订单日志配置。

`sessions.json` 描述交易时间段；`statemonitor.yaml` 描述何时开始接收、关闭接收、转历史。它们是不同用途的文件。`commodities.json` 中每个品种的 `session` 必须指向实际存在的时段模板；缺失会导致品种加载失败，随后它的合约也被跳过。

几个名字相似但职责不同的配置：

| 文件或字段 | 它解决什么问题 | 它不代表什么 |
|---|---|---|
| `contracts.json` | 合约、所属品种、到期日和数量限制；乘数与跳价通过品种关联取得 | 历史行情 |
| `commodities.json.session` | 品种用哪个交易时段模板 | CTP 登录 SessionID |
| `env.fees` | WT 理论盈亏使用的手续费模板 | 柜台最终扣费规则 |
| `env.riskmon` | 组合收益回撤后缩放目标仓位 | 自动保证金账户管理 |
| `traders[].riskmon` | 下撤单频率和数量限制 | 策略止损逻辑 |
| `bspolicy` | 买卖净量拆成开仓、平今、平昨 | 策略预测模型 |
| `executers[].policy` | 如何定价、拆单、超时撤单、追单 | 决定交易账户是哪一个 |
| `executers[].trader` | 执行器绑定哪条交易通道 | 仅日志显示名称 |
| `savedata` | 柜台委托、成交、资金、持仓写本地 | 持续行情存储 |

Parser、Trader、Executer 可以直接内嵌为数组，也可以用字符串引用外部 YAML。`WtRunner::config` 区分字符串与数组，再把相应子配置交给模块。把它们拆文件是为了集中维护通道与执行参数，不是强制“每模块必须一个文件”。


## 3．配置与部署层级

可以把部署分成三层：Python 包与原生库、运行配置与策略、运行产生的数据。它们不必混在同一个目录。

<!-- WT-TEXT-DIAGRAM:FOLD-START -->
<details class="wt-text-diagram" markdown="1">
<summary>展开文字版调用链或目录树</summary>

```text
simnow-03/
├─ common/                     品种、合约、交易时段、节假日、费用与主力规则
├─ datahub/                    QuoteFactory 或单独的数据中台入口及配置
├─ FUT_Data/                   中台写入的实时/历史行情；Python 引擎通过 reader 读取
├─ runtime/wtpy/               此次运行固定使用的 Python 包
│  └─ wrapper/linux/
│     ├─ libWtPorter.so         实盘/模拟盘 C++ 桥
│     ├─ libWtBtPorter.so       回测桥
│     ├─ libWtDataStorage.so    行情 reader/writer
│     ├─ libWtRiskMonFact.so    组合风控工厂
│     ├─ libWtMsgQue.so         监控事件 MQ 桥
│     ├─ parsers/               ParserUDP、ParserCTP 等
│     ├─ traders/               TraderCTP、TraderMocker 等
│     └─ executer/              WtExeFact 等执行单元工厂
├─ py_runner/
│  ├─ run.py / MyStrategy.py    启动与策略
│  ├─ config.yaml              总配置
│  ├─ tdparsers.yaml            行情接入方式/地址
│  ├─ tdtraders.yaml            柜台或本地模拟交易接口
│  ├─ executers.yaml            目标仓位如何落成委托
│  ├─ actpolicy.yaml            开平次序、限制规则
│  ├─ filters.yaml              组合/策略/代码过滤与干预
│  ├─ logcfg.yaml / Logs/       日志规则与输出
│  └─ generated/               策略、组合、执行器、柜台状态和 CSV
└─ monitor/                    监控独立进程；data.db、WtMonSvr.log
```

</details>
<!-- WT-TEXT-DIAGRAM:FOLD-END -->


Python 包可以装在虚拟环境，也可以用明确的 `PYTHONPATH` 指向 `runtime`。不要让默认搜索路径误载另一套上游 wtpy 包及旧原生库。数据中台与 Python 引擎使用同一套交易时段、合约信息和同一个存储根目录。

| 配置项 | 谁读取 | 依赖关系 |
|---|---|---|
| `logcfg.yaml` | `WtEngine` 构造时传给 `init_porter` | 在 `init()` 读取总配置之前已经生效 |
| `config.yaml/basefiles` | Python 管理器与 C++ WtRtRunner | 合约必须对应有效品种；品种 session 必须存在于 sessions.json |
| `data.store.module/path` | `WtDtMgr::init` | 模块加载 reader，path 对应中台存储根目录 |
| `env` | C++ 引擎 | CTA 类型、驱动时段、费用、过滤器和组合风控 |
| `parsers` | `ParserAdapter` | 可指向 YAML，也可内嵌数组；UDP 配置明确中台 IP、订阅端口及本地接收端口 |
| `traders` | `TraderAdapter` | 交易通道 ID、module、账户/前置/认证或本地撮合参数 |
| `executers` | `WtLocalExecuter` 等 | `trader` 必须与交易通道 ID 一致；policy 指定执行单元工厂、定价、限量与撤单 |
| `bspolicy` | `ActionPolicyMgr` | 本版本装配时必需；定义开平处理规则 |
| `notifier.url` | C++ EventNotifier | 必须与监控组合 MQ URL 对应；它与行情 UDP 地址无关 |
| Python 策略参数 | `run.py` / 策略构造 | 通过 `add_cta_strategy` 添加，不能只写在 `strategies.cta` 中就自动导入 Python 类 |

`WtEngine.init(folder, cfgfile)` 中的 folder 只用于拼接显式传入的 `contractfile/sessionfile/commfile` 等可选覆盖项；它不会自动把所有配置路径都改成相对于 common。未覆盖的 `basefiles` 路径仍取自 config.yaml。配置中的一般相对路径以进程工作目录为基准，而不是以 YAML 所在目录为基准。

原生插件有两种基准。`ParserAdapter/TraderAdapter` 先查当前运行目录下 `parsers/` 或 `traders/`，找不到再查库安装目录；`WtDtMgr` 的 reader 模块直接从安装目录找。`WtRtRunner::init` 的安装目录来自加载的 WtPorter 所在目录。部署时应明确固定整套包和库，不能只在工作目录放一个 WtPorter 就假设所有模块都从那里加载。


实际 simnow-03 使用 `run/`，而非示例树中的 `py_runner/`；当前组合风控工厂关闭，未把推荐树中的 libWtRiskMonFact 当作已经部署启用。实际文件清单和启动命令见 09。
