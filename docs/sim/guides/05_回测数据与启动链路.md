## 1．中台数据与下载 CSV 怎样进入回测

### 1.1 先看文件用途，不要只看扩展名

| 数据 | 用途与读法 | 回测准备方式 |
| --- | --- | --- |
| `FUT_Data/rt/ticks/SHFE/rb2701.dmb` | 当日实时 Tick 数据块，以 mmap 提供实时读写 | 回测历史读取器不会自动读取它；等中台正式收盘转储，或停止写入后用 WtDataHelper 读取并制作历史快照 |
| `FUT_Data/rt/min1/SHFE/rb2701.dmb` | 实时 1 分钟 K 线块 | 同上，转换为历史 DSB 后回放 |
| `FUT_Data/his/ticks/SHFE/20261013/rb2701.dsb` | 历史 Tick 文件；含文件头、压缩数据等 | `mode: wtp` 的回测读取器直接读取 |
| `FUT_Data/his/min1/SHFE/rb2701.dsb` | 历史 1 分钟 K 线 | `mode: wtp`，用历史仓库根目录 `FUT_Data/`，不是 `FUT_Data/his/` |
| 交易所或供应商 K 线 CSV | 列名、时间口径可能不同 | 先整理成 WT 列名与文件命名，再 `mode: csv` 或 WtDataHelper 转 DSB |
| 中台 Tick CSV、供应商 Tick CSV | CSV 不等于自动可回测 | 先映射成 `WTSTickStruct`，用 `WtDataHelper.store_ticks` 生成 DSB；当前 Tick 加载器已停止直接解析 CSV |

`.dmb` 是实时二进制数据块，`.dsb` 是历史二进制数据块。它们都不是 CSV。不能只改扩展名，也不能把一个还在扩容、写入的 mmap 文件当作稳定历史快照。

WT 自带工具已经有 `read_dmb_ticks`、`read_dmb_bars`、`read_dsb_ticks`、`read_dsb_bars`、`store_ticks`、`store_bars`、`trans_csv_bars`、`resample_bars`，不需要再写另一套二进制解码器。工具在 `wtpy/wrapper/WtDtHelper.py`，Python 类名是 `WtDataHelper`，内部调用 `WtDtHelper` 原生库。`store_ticks` 需要首条 WT Tick 结构的指针与条数，并不是把 CSV 路径直接传给它。

**核心源码，VM `src/WtDataStorage/WtBtDtReader.cpp:67、87`：**

```cpp
// read_raw_bars
ss << _base_dir << "his/" << PERIOD_NAME[period]
   << "/" << exchg << "/" << code << ".dsb";
// read_raw_ticks
ss << _base_dir << "his/ticks/" << exchg
   << "/" << uDate << "/" << code << ".dsb";
```

这两条实际路径说明，`configBTStorage(mode="wtp", path="../FUT_Data/")` 后，播放器通过 `HisDataMgr` 加载 `libWtDataStorage.so`，查找 `createBtDtReader`，创建 `WtBtDtReader`。它读取 `his` 文件，解压为 `WTSBarStruct` / `WTSTickStruct` 数组，回放器再缓存和推送。这里不是启动实盘的 mmap 读取器。

### 1.2 CSV 模式有两条不同路径

K 线 CSV，例如标准策略代码 `SHFE.rb.2701`：

```text
storage/
├── csv/SHFE.rb.2701_m1.csv
└── his/min1/SHFE/rb2701.dsb     ← 首次成功解析 CSV 后的缓存
```

`cacheRawBarsFromCSV` 先检查历史 DSB；找不到才解析 CSV，并自动写出 DSB。因此后来修改 CSV，却留下旧 DSB，可能继续使用旧数据。应明确数据更新流程，重新生成对应缓存，避免把参数变化误判为策略结果变化。

读取器按字段名取值，推荐完整表头：

```csv
date,time,open,high,low,close,volume,turnover,open_interest,diff_interest,settle
```

`date`、`time` 对应那根 K 线的实际时间和收盘分钟；价格用原始数值，成交量、成交金额及持仓量使用供应商实际口径。夜盘必须区分自然日期与交易日，不能简单把所有晚上行情的 date 改成次日。连续合约还依赖 `hots.json` 的换月规则。仅为了让文件能读就补零，会影响策略信号、成本估计和成交模型。

Tick 在 `mode="csv"` 下的路径反而是：

```text
storage/bin/ticks/SHFE.rb.2701_tick_20261013.dsb
```

VM `HisDataReplayer.cpp:3418` 的函数仍叫 `cacheRawTicksFromCSV`，但实际只读上述 DSB；CSV 解析代码已经注释掉，缺文件会直接报错。**名称里的 CSV 不代表 Tick CSV 仍被支持。** `mode="wtp"` 则读前述 `his/ticks/交易所/交易日/原始合约.dsb`，两种模式的 Tick 目录不能混用。

### 1.3 播放器如何把行情推给 CtaMocker

```text
DSB / 整理后的 K 线 CSV
    ↓ 历史文件读取、解压、缓存
HisDataReplayer
    ↓ 推进历史日期、时间和交易日；维护订阅游标
    ├─ handle_tick → CtaMocker::handle_tick
    ├─ handle_bar_close → CtaMocker::handle_bar_close
    ├─ handle_schedule → CtaMocker::handle_schedule
    └─ handle_session_begin/end → 开收盘处理
```

策略在 `on_init` 调用 `stra_get_bars(..., isMain=True)`，指定计算调度所用的主 K 线；`stra_sub_ticks` 订阅 Tick。播放器并不是加载完文件就把全量历史交给策略随意访问，而是随历史时钟移动可见游标，切片接口只向策略暴露已经推进到的部分。

有主 K 线时，`run_by_bars` 在相邻主 K 线之间回放真实 Tick（`tick: true`）；没有真实 Tick 时，会调用 `simTicks` 按 **开→高→低→收** 生成合成 Tick。没有主 K 线而启用 Tick 时，走 `run_by_ticks`，逐交易日调用 `replayHftDatasByDay`。K 线闭合时 `onMinuteEnd` 推送 Bar，并调用计算调度。

**Bar 合成 Tick 不是历史真实走势。** 高低点实际先后不可从一根 K 线还原，混合 m1/m5 时还有时序限制。因此仅有 Bar 数据适合策略逻辑与粗略成本研究；本文改造的 `causal_touch` / `volume_limited` 要求真实买卖报价，不会用合成盘口或 last 价填补真实报价缺失，只有 Bar 数据可能一直没有成交。原 `legacy_cta` 则沿用原有合成 Tick 的价路径。

VM `HisDataReplayer.cpp:1850、1966` 在真实 Tick 回调前明确将 `_tick_simulated = false`，避免第一条真实 Tick 被错误判为 Bar 合成行情。真实 Tick 核心派发为：

```cpp
update_price(stdCode, nextTick.price);
WTSTickData* newTick = WTSTickData::create(nextTick);
newTick->setCode(stdCode);
_tick_simulated = false;
_listener->handle_tick(stdCode, newTick, 0);
newTick->release();
```

来源：VM `HisDataReplayer.cpp:169(init)、647(prepare)、675(run)、739(run_by_ticks)、770(run_by_bars)、1225(simTicks)、1751(replayHftDatasByDay)、1999(onMinuteEnd)、3684(cacheRawBarsFromCSV)`；VM `HisDataMgr.cpp:12、47、62`。


## 2．wtpy 回测启动：Python 写策略，C++ 回放与记账

回测入口一般是 `runBT.py`，不需要启动 QuoteFactory、ParserUDP、TraderCTP 或执行器。`WtBtPorter` 原生库在 Python 进程里运行，不是另起一个 `WtRunner` 可执行程序。

建议的学习目录：

```text
backtest/
├── runBT.py                      # 创建引擎、配置、注册策略、回放、分析
├── strategies/simple.py          # BaseCtaStrategy 子类
├── configbt.yaml                 # 回测时间、数据源、基础文件、费用
├── logcfgbt.yaml                 # C++ 日志输出设置
├── common/
│   ├── sessions.json             # 交易时段模板
│   ├── commodities.json          # 乘数、跳动、交易类别、对应session
│   ├── contracts.json            # 分月合约、到期信息
│   ├── holidays.json             # 交易日历
│   ├── hots.json                 # 仅连续/主力回测需要其相应规则
│   └── fees.json                 # 开仓/平仓/平今费率与最低费
├── storage/                      # 采用 CSV 模式时的 csv/、bin/、his/缓存
├── outputs_bt/策略名/            # C++ 回测结果
└── reports/                      # 明确指定给分析器的输出报告目录

wtpy 安装目录/wrapper/
├── libWtBtPorter.so              # ctypes→C ABI→C++回测核心
├── libWtDataStorage.so           # mode=wtp 时的历史读取器
└── libWtDtHelper.so              # 数据转换用，非每次回测都必须启动
```

`common` 可以放在同级公共目录，行情仓库也可以在别处；关键是 YAML 中路径与运行工作目录相符。`engine.init(common_folder, cfgfile)` 读取 `cfgfile`，只有显式给 `commfile` / `contractfile` / `sessionfile` 等覆盖参数时才会把它们拼到 folder；不会自动把 YAML 已写的所有路径统一改成 common_folder。Python 的 ProductMgr、ContractMgr、SessionMgr 与 C++ 端会各自读取基础文件，应使用相同版本和编码。

| 配置 | 被谁读取 | 作用与依赖 |
| --- | --- | --- |
| `logcfgbt.yaml` | `WtBtEngine` 构造→原生日志初始化 | 日志目录、级别、策略日志模板 |
| `configbt.yaml.replayer.basefiles` | Python 基础数据管理器及 C++ `HisDataReplayer::init` | sessions 先于 commodities，品种先于 contracts；连续合约依赖 hot/rules |
| `replayer.stime/etime` | 历史播放器 | `yyyymmddHHMM`；`configBacktest` 可在提交前覆盖 |
| `replayer.mode/store.path/store.module` | 历史播放器、HisDataMgr | CSV路径或历史仓库；CSV 模式 module 不生效 |
| `replayer.tick` | 历史播放器 | 是否优先回放真实 Tick，不能仅凭磁盘有 Tick 判断已启用 |
| `replayer.fees` | 历史播放器 | `calc_fee` 按实际数量、开平类型/平今计算费用 |
| 策略构造参数 | Python 策略 | 合约、周期、信号参数、风险预算等 |
| `set_cta_strategy` 参数 | Python Wrapper→C ABI→CtaMocker | 滑点、成交模型、事件延迟、参与率、持久化开关 |
| `outDir` | 回测原生辅助模块 | 输出根目录，默认为 `./outputs_bt` |

最小启动代码，数据与参数必须按实际情况填写：

```python
engine = WtBtEngine(EngineType.ET_CTA, outDir="./outputs_bt")
engine.init("./common/", "configbt.yaml")
engine.configBacktest(202610130900, 202610131500)
engine.configBTStorage(mode="wtp", path="../FUT_Data/")
engine.commitBTConfig()
engine.set_cta_strategy(strategy, slippage=1,
                        fill_model="volume_limited",
                        event_delay=0, participation_rate=0.10)
engine.run_backtest(bAsync=False)
engine.release_backtest()
```

这段 `fill_model` 写法要求 **VM 当前改造版 wtpy + 对应 libWtBtPorter.so**。本机 `F:\XiangMu\Trader\wtpy\wtpy\WtBtEngine.py:371` 仍是旧签名，没有这三个新增参数；直接在该旧 Python 包上使用会报 TypeError。不能拿改造版 Python 配旧库，或按新版文档假定所有安装位置都已更新。VM Wrapper 支持 `WTPY_BT_PORTER_LIB` 显式选择构建库；未设置时从 wrapper 安装目录加载平台对应库。

实际调用顺序：

```text
1 runBT.py 创建 WtBtEngine(ET_CTA)
  → WtBtWrapper.__init__ → ctypes.cdll.LoadLibrary(WtBtPorter)
  → initialize_cta：注册 Python 回调、调用 init_backtest

2 engine.init / configBacktest / configBTStorage
  → Python 读 YAML、加载基础数据管理器、修改配置字典

3 commitBTConfig
  → json.dumps → wrapper.config_backtest(JSON, False)
  → C ABI config_backtest → WtBtRunner::config
  → HisDataReplayer::init：基础文件、时间、行情源、手续费

4 set_cta_strategy
  → wrapper.init_cta_mocker [legacy / v2 / v3]
  → WtBtRunner::initCtaMocker → new ExpCtaMocker
  → configure_fill_model → register_sink
  → Python 保存 CtaContext(ctxid, strategy, wrapper, engine)

5 run_backtest
  → C ABI run_backtest → WtBtRunner::run
  → HisDataReplayer::prepare → handle_init → 策略 on_init 订阅数据
  → HisDataReplayer::run → 历史事件回放

6 回测结束
  → handle_replay_done → dump_outputs / dump_stradata / dump_chartdata
  → Python on_backtest_end；再按需运行 WtBtAnalyst
```

`run_backtest` 在配置尚未提交时会自动提交；不要提交后再改参数并期待第二次 commit 生效。示例选同步模式，返回时回放已经结束，才分析结果。异步模式必须另行等回测完成，不能刚启动就读取不完整文件。

跨语言有两个方向：

```text
历史事件 → CtaMocker → ExpCtaMocker
 → WtBtRunner::ctx_on_tick / ctx_on_calc
 → ctypes 注册的 callback → WtBtWrapper.on_stra_tick/on_stra_calc
 → CtaContext.on_tick/on_calculate → Python 策略

Python 策略设置目标
 → CtaContext.stra_set_position → WtBtWrapper.cta_set_position
 → C ABI cta_set_position → CtaMocker.stra_set_position
 → 待成交目标 → 回放事件撮合 → apply_fill
```

来源：VM `wtpy/WtBtEngine.py:149、183、192、279、372、416`；VM `WtBtWrapper.py:29、34、initialize_cta、init_cta_mocker`；VM `WtBtPorter.cpp:172、179`，`WtBtRunner.cpp:268、448、460、527`；VM `ExpCtaMocker.cpp:25、49、70`。本机 `wtpy/CtaContext.py:130、156、262、319`。


## 3．结果文件怎样产生，分析在哪里

回测中交易、平仓、资金和持仓日志先写入 C++ 字符串流；结束时 `CtaMocker::handle_replay_done` 调用 `dump_outputs`，拼接 CSV 表头与行，写到 `outDir/策略名/`。这与运行盘 TraderAdapter 收到柜台回报时写 CSV 是两套输出逻辑。

| 文件 | 写入内容 | 解读 |
| --- | --- | --- |
| `signals.csv` | 策略目标、生成时刻、标签 | 目标不是已成交订单 |
| `trades.csv` | 每笔回测开平成交、价格、数量、费用 | 反手可拆成平旧仓和开新仓两行 |
| `closes.csv` | 每段持仓从开到平的盈亏、最大浮盈/浮亏、标签 | 用于交易统计，不等于逐 Tick 权益 |
| `funds.csv` | 每交易日平仓盈亏、持仓浮盈、净累计盈亏、费用 | `dynbalance` 是累计净盈亏口径，不自动包含任意初始本金 |
| `positions.csv` | 每日各合约实际仓位与盈亏 | 与策略目标可能不一致 |
| `fill_decisions.csv` | 撮合尝试及等待/拒绝状态 | 有行不代表已成交 |
| `fill_audit.csv` | 实際记账量与报价、成交价及成本 | 只计真正 apply_fill 的变化 |
| `equity_events.csv` | 每 Tick 净盈亏、目标、实际、缺口 | 新增逐事件审计；长周期有资源边界 |
| `target_replacements.csv` | 目标覆盖、旧目标未成交剩余 | 失效量不是成交量 |
| `ud_策略名.json` 等 | 策略保存的用户数据与图表/标记 | 不是监控 SQLite 用户表 |

`persistData=False` 会使 `dump_outputs` 不导出这些常规结果。回测过程还可能导出进度 JSON 或向事件 notifier 推送状态；是否存在由配置与参数决定，不必要求每个实验都生成所有文件。

绩效分析器是事后读文件：

```python
analyst = WtBtAnalyst()
analyst.add_strategy("simple", folder="./outputs_bt/",
                     init_capital=50000, rf=0.02,
                     annual_trading_days=240)
analyst.run_new(outFileName="./reports/simple.xlsx")
```

它读取 `./outputs_bt/simple/{funds,closes,trades}.csv`，以用户提供的 `init_capital` 计算收益率等，写 Excel，另把 `summary.json` 写回策略结果目录。不指定 Excel 路径时，默认报告在当前工作目录。**分析器的 initial capital 仅供计算收益率，不会倒过来给 C++ 成交账本加入资金约束。** 日内短测试没有足够交易日、平仓记录时，不宜把分析器能生成报告等同于统计结论有意义。

来源：VM `CtaMocker.cpp:380(dump_outputs)、461(log_trade)、468(log_close)、864(handle_replay_done)、1567(日资金/持仓)`；本机 `wtpy/apps/WtBtAnalyst.py:1607(add_strategy)、1615(run_new)、1643(summary)`。
