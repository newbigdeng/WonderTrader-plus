# 本地模拟盘修复：成交字段、退出顺序与状态恢复

9 月 30 日实验能开平仓，却暴露累计量为负、日期为零、退出崩溃和快照滞后。10 月 2 日基于 `c7c5619` 加工作区补丁修复，14 个集成场景与 54 项单元测试通过。本文把根因、改法与验证放在一起；本次整理没有新增源码修复。

## 1. 累计成交量为什么会变成负数

一手单显示 traded=-1，三手单显示 -3，但实际成交流水数量为正。沿 `TraderMocker.cpp` 的分笔撮合更新发现，同一笔成交量被用于减少累计已成交字段。

剩余量应该减，累计已成交量应该加。修复后每次成交 q 同时满足：累计成交增加 q，剩余量减少 q，总委托量守恒。三手订单分三次各成交一手，最终累计字段为 3，开平各一张订单、各三条成交。

这次验证同时看委托终态与成交流水。只看持仓归零，可能漏掉回报字段错误。

## 2. 日期与交易日分别表示什么

旧委托和成交日期没有赋值，输出为 0。修复从同一次本地时钟采样取得自然日和毫秒时间，避免跨午夜分别采样造成日期、时间不一致。

自然日是这件事在本地何时发生，交易日是所属结算周期；夜盘可能属于下一交易日。测试专门设置二者不同，核对字段语义。真实柜台夜盘归属仍需接入后验证。

首轮测试还遇到容器缺 IANA 时区文件，改用 POSIX 时区后重测。这属于测试环境处理，历史失败保留，没有记为产品日期修复的新缺陷。

## 3. 为什么收到 SIGINT 后会崩溃

问题不是一个 stop 标志：时钟、网络、writer、广播和撮合线程仍可能回调已经销毁的对象。旧路径既可能因线程尚可 join 而 terminate，也可能在对象析构后发生纯虚调用。

沿引用方向建立停止顺序：先封外部输入，唤醒并停止工作线程，等回调和任务结束，再释放被调用对象。主线程执行有序关闭，模块持有自己的线程并 join；不能用 sleep 代替完成确认。

修复覆盖 WtRunner、QuoteFactory 及 parser、engine/ticker、writer、caster、监控与交易接口。等待期间仍要允许已接纳任务完成，避免下游先停导致上游永远无法排空。

### 跨线程对象为什么还会访问已释放内存

`WTSPoolObject` 的旧线程局部池在生产线程退出时释放存储，而其他线程可能仍持有对象。引用计数保住了对象的逻辑身份，却没保住承载它的池内存。

改为共享池状态，使池的存活覆盖所有借出的对象；线程局部入口结束不再提前释放仍被引用的底层存储。由于对象布局与池契约改变，相关模块必须成套重新编译。

独立 ASan 对照中旧版退出码 1，新版 0，定位到的 use-after-free 消失。这是对应对象池场景的证据，完整应用所有路径仍需独立验收。

## 4. 最终状态应该在什么时候保存

策略理论目标和模拟通道实际持仓是两本账。目标 3、只成交 1 手时，前者仍是 3，后者是 1；保存时强行写成一样会丢掉剩余执行责任。

正常停止先等时钟和引擎任务结束，再保存策略最终状态；模拟器停止撮合和 I/O 后保存实际通道持仓。重启保持策略、执行器、通道 ID 及状态目录，重新计算目标与实际差额。

原运行中的 `save_data` 顺序仍可能早于资金汇总或信号删除。补最终保存修复的是正常关闭快照，运行中资金快照滞后（SIM-04）仍待修复。

## 5. 用哪些场景证明修改有效

| 场景 | 结果与验证点 |
|---|---|
| 基线一手开平 | 两张终态订单、两条成交，最终空仓，字段正确 |
| 三手分笔 | 两张终态订单、六条一手成交，累计成交字段各为 3 |
| SIGINT、SIGTERM、空闲退出 | 正常停止返回 0，线程可被唤醒并完成 |
| 突发 200 条后关闭 | 存储原生块读出全部 200 条 |
| 留一手、重启保持、再次平仓 | 重启没有新增开仓，最后只新增一次平仓 |
| 目标三手但一手时退出 | 理论目标 3 与通道持仓 1 分别保存；重启只补两手 |
| HFT/SEL 空闲退出 | 公共停止接口的对应兼容场景通过 |
| 自然日与交易日不同 | 日期非零，与同次时间戳采样一致 |

共 14 场景、28 次进程关闭返回 0，没有用强杀换取退出成功。54 项单元测试由 48 项 CTA 模型、3 项费用和3项池生命周期测试组成。另有独立初始化释放检查通过。

订单 CSV 只记录终态，三手单仅成交一手时可能尚无订单行，但已有成交行；数量验收必须结合回报和流水。
